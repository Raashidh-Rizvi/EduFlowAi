5. TOP VIVA EXAM QUESTIONS & DETAILED ANSWERS
--------------------------------------------------------------------------------
Q1: Why do you have both XpTransactions (ledger) and StudentXp (total)?
A1: XpTransactions is an append-only transaction ledger (like a bank statement)
    that records every single reward event, source type, and timestamp. It is
    immutable and prevents fraudulent tampering. StudentXp stores the cached
    aggregated total XP and level so dashboard and leaderboard queries execute
    in O(1) time without expensive SQL SUM aggregates on every page load.

Q2: How do you prevent a student from viewing or claiming another student's data?
A2: In GamificationController, we never trust the studentId passed in the URL.
    We extract the caller's verified ID from the cryptographically signed JWT
    claims (ClaimTypes.NameIdentifier). If the caller's ID does not match the
    requested studentId (and user is not an Admin), the controller immediately
    aborts and returns HTTP 403 Forbid().

Q3: Why must the AI Agent NEVER directly award XP or update grades?
A3: Large Language Models and AI agents are probabilistic and can hallucinate or
    be manipulated through prompt injection. Financial and reward ledgers require
    strict ACID guarantees in the relational database. The AI agent only analyzes
    student telemetry to recommend the next best action; XP is only awarded by
    the core .NET backend through authenticated business logic.

Q4: How does the Flutter mobile application handle authentication & tokens?
A4: ApiService uses FlutterSecureStorage (backed by Android Keystore on Android
    and Keychain on iOS) to store the JWT securely. A custom Dio interceptor
    automatically reads this token and injects 'Authorization: Bearer <token>'
    into the headers of all outbound HTTP requests.

Q5: What happens when a student reaches 500 XP?
A5: In LevelCurve.cs, 500 XP is the exact threshold for Level 2. When AwardXpAsync
    is invoked, it calculates the new level from total XP. If newLevel > oldLevel,
    it sets LevelUpOccurred = true in the returned DTO, which informs the
    client frontend to trigger celebratory UI animations.
